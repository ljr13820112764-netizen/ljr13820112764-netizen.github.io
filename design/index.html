双端设计稿 36 页

两个作品各有一套完整的设计系统与双端设计稿：「准绳」14 页（桌面 11 + 移动 3，暖纸设计系统）与「知数」22 页（桌面 17 + 移动 5，冷白钢蓝单主色）。设计稿与可运行 Demo 同源同数据——不是另画一套图去配 Demo，而是同一份界面在两种形态下的定稿。

2026-10 · 独立完成：信息架构 / 设计系统 / 双端页面 / 交付（Pixso）· 两件作品同批经四视角评审 25 项修订

01

两套设计系统

准绳 · 暖纸仪器画布 #FAF9F6 · 白顶栏 · 赭色主色 #B45309 · 描边 #ECE7DE · 标签 #7E766A
现场光线复杂、长时间盯屏，暖白底比纯白更耐看；赭色只用于「要注意的事」。
知数 · 冷白钢蓝画布 #F7F8FA · 白卡 · 唯一钢蓝 #4A7596 · 选中 #EDF3F8 / #2E526B
企业软件需要「冷静、可审计」的第一印象，全站只有一个强调色，避免和数据语义色抢注意力。

两套都按灰度先行设计：先用间距、字号、字重立层级，最后才上色；间距取 4/8/16/24/32 固定档，不出现 13px、17px 这类随手值。

02

「准绳」双端设计稿 · 14 页

  • 信息架构：导航收敛为五个平级入口——整改记录 / 笔记 / 查规范 / 规范库 / 历史；表格、看板、时间线、统计、检查模板降为「整改记录」下的视图切换，不再各占一个一级入口
  • 一处刻意例外：01 整改详情采用专注模式（无全局侧栏），因为该页已有 260px 记录列表面板，再加侧栏会把详情挤成三栏
  • 与 Demo 同源：页面里的记录数、期限天数、条文关联都由同一份演示数据算出，设计稿不会出现「好看但对不上」的数字
03

「知数」双端设计稿 · 22 页

  • 全模块 HCM 的界面骨架：侧边栏按「我的工作 / 人才管理 / 人事运营 / 数据与治理 / 关于」五组，只显示当前角色可用项
  • 可信答案层落在界面上：答案卡把数据口径、数据版本、策略版本、样本门槛与抑制说明放在同一张卡里——权限之外的人看到的是「被抑制」，而不是猜出来的近似值
  • 敏感信息的分寸：薪酬页先给带宽与聚合，个人精确值需审批后可见；差异只给类型标签，不给具体金额
04

四视角评审：改了什么

36 页出图后，按产品战略 / 研发测试 / 法务合规 / UI·UX 四个视角各评一遍，去重核验后修掉 25 处。评审是 AI 分角色模拟，不是真实评审委员会。

类别典型问题 → 处理
数字一致性移动端四部门合计与页头 207/224 对不上、审批「最长等待 23 小时」与列表「剩 3 小时」矛盾、合同到期 149 / 144 两处不一 → 全部改为同一数据源计算
流程与状态审批详情与批量勾选共用一套高亮 → 拆成独立选中态；四个时间口径 → 拆成「审批 24h 时限」与「授权 72h 有效期」两个命名时钟
合规表述答案卡补「不构成人事决定依据」；「证据包」改名「留痕包（非法律证据）」并写明三项不证明；审计留存统一为 24 个月、可调 36 个月
可用性与图表移动端滚动被底栏切断 → 改可滚 + 底部内边距；统计图补 Y 轴刻度与网格；触控目标统一放大到 40px 以上
验证链测试脚本补期望总数守卫与脚本指纹校验，防止删断言后「假绿」

仍有未处理项并如实列出：对比度 token 未统一、9–10px 功能文字、组织图交互、跨页组件走样——这些属于「整体返工一遍 token 与组件」，改一处要全 36 页重核，留到下一轮单独做。
